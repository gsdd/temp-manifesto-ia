Page module taxonomy (draft for review)

Wireframe tool, not a live URL. One row per unit type: what it is for, what shape it takes in the wireframe, what it does when clicked, and what it must never be. The example column renders each unit with the shared wireframe CSS, so it shows what ships today, including the places where today's shape breaks the rule. Full reasoning and the scorecard are in docs/wireframe-fresh-review.md, section 5.

A unit is classified by four questions, in order:

  1. Does the whole unit go somewhere when clicked? Yes: Link or Card. No: next question.
  2. Does it do something on this page (submit, filter, toggle, page, accept)? Yes: Control. No: next question.
  3. Is it framed content that stands alone (a number, a quote, a figure, a placeholder)? Yes: Display. No: Text.
  4. If it goes somewhere: is it a title plus one supporting line plus an optional media slot, in a frame? Yes: Card. No: Link.

Rules that follow: solid border means clickable; dashed means placeholder; one primary button per screen and one secondary style for everything else; tags go somewhere and filters change something, so they never share a shape; a destination appears once per page in one shape; frameworks are Display and are drawn once; process phases are one module; link lists look like link lists at rest; every block carries a label; the catalogue defines each unit, it does not only show it.
